# Airtel SYNC PULSE — Stadium Network Command Centre

> **Predict. Distribute. Prioritise. Protect.**

A full-stack interactive decision-support prototype for the Airtel SYNC Case 1 "Stadium Surge" — planning a 5G network for a 1,00,000-fan IPL cricket final, Rs 4 crore budget, 60 days.

> ⚠️ **This is a software simulation and decision-support prototype. It does NOT control Airtel infrastructure.**

---

## Quick Start

### Prerequisites
- Python 3.11+  
- Node.js 18+  
- macOS (tested on Apple Silicon and Intel)

### 1. Backend (FastAPI)

```bash
# From the project root (sync-pulse/)
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt

# Run the API server
uvicorn backend.app.main:app --reload --port 8000
```

The API will be available at **http://localhost:8000**  
Swagger docs at **http://localhost:8000/docs**

### 2. Frontend (React + Vite)

```bash
# In a new terminal, from the project root
cd frontend
npm install
npm run dev
```

Open **http://localhost:5173** in your browser.

## Run Tests

```bash
# From the project root, with venv active
source .venv/bin/activate
python -m pytest backend/app/tests/test_all.py -v
```

All 41 tests should pass, including:
- Section 4 capacity numbers (Airtel users, demand, cell counts)
- Section 5 budget totals (Rs 336.5 L committed, Rs 63.5 L reserve)
- Risk scoring rules
- Data loader integrity (32 rows, 8 sites, 4 UPI phases)

### Judge Script

```bash
source .venv/bin/activate
python judge_check.py
```

## Data Ground Rules

Every number on screen carries one label:

| Label | Meaning |
|---|---|
| **DATASET** | Directly from Sync_V1.xlsx |
| **ASSUMPTION** | Planning input (budget, spectrum, sharing) |
| **MODEL** | Calculated from assumptions |
| **TARGET** | Design goal |
| **SIMULATION** | Generated by bounded interpolation |

No value is invented. Blank cells in the Excel show "no data".

## Demo Story (~90 seconds)

Click **Demo (~90s)** in the top-right corner. The app automatically walks through:

1. **Overview** — demand, budget, cell-count KPIs  
2. **Digital Twin** — innings break: M1/M2/M3 at critical load, M6 has spare capacity  
3. **Monitoring** — load spikes at 21:00, 5G success collapses  
4. **Prediction** — M1/M2/M3 → CRITICAL risk  
5. **Orchestrator** — SYNC PULSE activated: load balance → COWs → EN-DC → QoS  
6. **UPI** — 7.11% failure peak, priority QoS caveat  
7. **Budget** — Rs 336.5 L committed, Rs 63.5 L reserve  
8. **Impact** — gap vs targets, key findings  

Click **Reset Demo** at any time to explore manually.

## Technical Notes

- **No black-box ML**: 32 rows → rule-based risk score + simple linear fit with leave-one-site-out CV only
- **NSA 5G anchor**: Idle-mode priority does NOT remove the LTE anchor dependency; SA 5G is longer-term
- **UPI caveat**: Network QoS cannot guarantee end-to-end UPI success
- **Identical runs**: All calculations are deterministic; running twice gives identical results
